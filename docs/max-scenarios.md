# Сценарии MAX-бота и AI-агента «Машина времени»

## Принципы (ограничения безопасности)

- Агент NEVER не ставит диагноз по переписке; диагноз — после осмотра мастером.
- Агент NEVER не называет точную итоговую цену; даёт ссылку на прайс.
- По ключевым симптомам безопасности (тормоза, перегрев, течь масла) —
  немедленный эскалейт на оператора + дисклеймер.
- Любой пользователь может написать «оператор» для переключения на человека.
- AI-слой включается через `AI_ENABLED=true`; по умолчанию работает rule-based
  детерминированный бот.
- Логи переписки пишутся в таблицу `max_messages`, лиды — в `leads`.

## Слои

1. **Rule-based bot** — детерминированная конечная машина состояний:
   приветствие → имя → телефон → услуга → симптомы → подтверждение.
   Также: ключевые слова (прайс, оператор, срочные симптомы).

2. **AI-agent layer** — если rule-engine не сработал и AI включён, RAG через
   LLM, промпт которого ретривит записи из `knowledge_items`
   (см. `internal/aiagent/agent.go::tryAI`). Ответ обрезается лимитом
   `AI_MAX_TOKENS` и снабжается дисклеймером.

## Основные сценарии пользователь

### A. Заявка на ремонт (лид)
```
User: привет
Bot:  Здравствуйте! Это «Машина времени» 🕒 ...
      [Записаться][Прайс][Контакты][Оператор]
User: записаться
Bot:  Отлично, запишем вас. Как вас зовут?
User: Андрей
Bot:  Спасибо, Андрей. Оставьте телефон для связи:
User: +7 916 1234567
Bot:  Какая услуга нужна? (диагностика, ТО, тормоза, подвеска...)
User: передние тормоза скрипят
Bot:  Опишите кратко, что беспокоит в авто (необязательно)... «далее»
User: скрип при торможении на холодную
Bot:  Готово! Передаю заявку менеджеру — он подтвердит дату и время...
      ℹ️ Точный диагноз и цена — после осмотра автомобиля мастером.
→ leads(channel=max, answer={service:"передние тормоза", symptom:"скрип..."})
→ MAX notify admin chat
```

### B. Срочный симптом → эскалация
```
User: машина не тормозит как раньше, педаль мягкая
Bot:  Это может быть вопрос безопасности. Передаю вас специалисту...
      ℹ️ Точный диагноз и цена — после осмотра автомобиля мастером.
→ Escalate = true, оператор подключается к чату
```

### C. Вопрос по цене
```
User: сколько стоит замена масла?
Bot:  Актуальные цены публикуем в разделе «Прайс-лист» на сайте.
      Точную смету сформируем после осмотра...
```

### D. FAQ (KB + AI)
```
User: по какому адресу вы находитесь?
Bot:  Москва, ул. Гаражная 12. Запись — на сайте или здесь.
User: какие у вас часы работы?
Bot:  Мы работаем Пн–Сб 09:00–20:00, воскресенье — выходной.
```

### E. Handoff к оператору
```
User: оператор
Bot:  Переключаю вас на оператора 🔧 Подождите немного.
→ Escalate = true
```

## Состояние диалога
В демо-режиме хранится в памяти процесса (`seatStore`). Для горизонтального
масштабирования заменить на таблицу `sessions` (state jsonb, keyed chat_id) —
интерфейс агента от этого не меняется (`aiagent.Seat`).

## Webhook
- Endpoint: `POST /api/v1/max/webhook`
- Заголовок подписи: `X-Max-Signature` (HMAC секрет → проверено
  `max.VerifyWebhook`, constant-time).
- Payload нормализуется в `InboundMessage` (`max.ParseWebhook`) —
  адаптер читает `chat_id`, `from`, `message.text`.
- В prod не настроенная подпись → `401`. В dev — warn и пропуск
  для удобства локальной отладки taped-вебхуками.

## Подключение боевой интеграции
1. Зарегистрировать бота в MAX, получить `MAX_API_TOKEN`.
2. Настроить webhook в кабинете MAX на `https://<your>/api/v1/max/webhook`
   с секретом → `MAX_WEBHOOK_SECRET` того же значения.
3. `MAX_ENABLED=true`, `MAX_NOTIFY_CHAT_ID=<admin chat>`.
4. Реализовать `stubClient` → реальный HTTP-клиент:
   `SendMessage` POST `${MAX_API_BASE}/messages/sendText`,
   `SendMessageWithButtons` — эндпоинт inline-кнопок MAX.
   Интерфейс `max.Client` уже задан — менять вызовы не нужно.
